Product judgment is proven by products that ship. This report documents five AI products I took from problem statement to launch on my own in the past year, three of which still run in production daily. Each section states the problem, the design decision, and the measured result, with the dashboard and read date for every number.

1Lecture Companion

1.1Problem

The bottleneck for asking questions in class is input friction, not model capability. Students do not type while listening.

1.2Design

A question is compressed into one click on a transcript sentence. Multimodal retrieval fills in the whiteboard and formulas. The North Star is after-class review behavior, not in-class activity; cost is managed line by line in a usage ledger.

1.3Result

Multimodal retrieval shipped in 3 stages over two days with zero rollbacks (release log). ASR cost was cut to one quarter after optimization (usage ledger).

2xhs-threads

2.1Problem

Bookmarking is frequent; organizing almost never happens, because it requires the user to start.

2.2Design

Organizing becomes zero-label, proactive archiving: the user only saves. The AI threads bookmarks into trains of thought, writes the notes, and an independent reviewer model gates the output. Differentiation was established through a survey of four competitor types.

2.3Result

90% of model calls run on the light tier (call ledger). Cost per item is ¥0.05–0.10 (ledger range, pending re-measurement).

3Nous

3.1Problem

Message bots learn how you talk. None learn how you decide, which is where the real cost of replying sits.

3.2Design

A nine-dimension cognitive model drives a message agent: it judges whether to reply, drafts in your way, and raises a quality warning when you are about to say yes to something you will not do. Three clients: Feishu bot, Mac floating assistant, Web.

3.3Result

Behavior prediction accuracy rose from 49% to 71%. The correction flywheel is closed: user corrections feed the model.

4JobPilot

4.1Problem

The job search is blocked by people, not information. Existing tools stop at the behavior layer.

4.2Design

JobPilot plugs in a cognitive model and language samples to produce a personal diagnosis and messaging that sounds like the user. All six product trade-offs have a written rationale. Open source.

4.3Result

31 CLI commands and 544 tests, CI green (repository, 2026-09). A read-only live demo is public.

5MusiClaw

5.1Problem

Public ticketing data for Shanghai musicals exists but is never read as a product.

5.2Design

A data product that updates itself daily: seat-map snapshots, cast attribution analysis, four content pipelines feeding a real data account. What the AI may and may not decide is written down.

5.3Result

Four content pipelines run; every publication gets a fixed 24-hour review (operations SOP).

6Method

Four rules hold across all five products.

  1. Pain point before solution. Confirm which layer the bottleneck lives in before building. Get the layer wrong and no feature fixes it.
  2. Staged rollout and attribution. One layer of change per stage, so a problem points at its layer immediately.
  3. Define the metric before the number. Marks reviewed after class, not made in class. Daily actives by UV, not PV. Every reported number names its dashboard, metric and read date.
  4. Cost is a product parameter. Every model call logged and routed by task tier. A shadow run proves quality holds before cost is cut.
