Product judgment is proven by products that ship.

This manual documents five AI products I took from problem statement through development to launch on my own. Each chapter states the problem, the design decision, and the measured result. Figures are screenshots of the live products; tables list the figures with their sources.

Four rules hold across all five: pain point before solution; staged rollout and attribution; define the metric before the number; cost is a product parameter.

CHAPTER01

Lecture Companion

real-time lecture AI assistant · solo build

Problem

The bottleneck for asking questions in class is input friction, not model capability. Students do not type while listening.

Design

A question is compressed into one click on a transcript sentence. Multimodal retrieval fills in the whiteboard and formulas. North Star: after-class review behavior, not in-class activity. Cost is managed line by line in a usage ledger.

Result

Multimodal retrieval shipped in three stages over two days, zero rollbacks. ASR cost cut to one quarter.

CHAPTER02

xhs-threads

thought threads from Xiaohongshu bookmarks · solo build

Problem

Bookmarking is frequent; organizing almost never happens, because it requires the user to start.

Design

Zero-label, proactive archiving: the user only saves. The AI threads bookmarks into trains of thought, writes the notes, and an independent reviewer model gates the output. Differentiation established through a survey of four competitor types.

Result

Ninety percent of calls run on the light model tier; cost per item ¥0.05–0.10.

CHAPTER03

Nous

cognitive-twin message agent · three clients

Problem

Message bots learn how you talk. None learn how you decide, which is where the real cost of replying sits.

Design

A nine-dimension cognitive model drives the agent: it judges whether to reply, drafts in your way, and raises a quality warning when you are about to say yes to something you will not do. Feishu bot, Mac floating assistant, Web.

Result

Behavior prediction rose from 49% to 71%. The correction flywheel is closed.

CHAPTER04

JobPilot

AI job-search strategist · solo build · open source

Problem

The job search is blocked by people, not information. Existing tools stop at the behavior layer.

Design

A cognitive model plus language samples produce a personal diagnosis and messaging that sounds like the user. All six product trade-offs have a written rationale.

Result

31 CLI commands, 544 tests, CI green, public read-only demo.

CHAPTER05

MusiClaw

Shanghai musical-theatre market data · solo build

Problem

Public ticketing data for Shanghai musicals exists but is never read as a product.

Design

A data product that updates itself daily: seat-map snapshots, cast attribution analysis, four content pipelines feeding a real data account. What the AI may and may not decide is written down.

Result

86 shows snapshotted every day; every publication gets a fixed 24-hour review.

RULE 1Pain point before solution.

Confirm which layer the bottleneck lives in before building. Get the layer wrong and no feature fixes it.

RULE 2Staged rollout and attribution.

One layer of change per stage, so a problem points at its layer immediately.

RULE 3Metric before number.

Marks reviewed after class, not made in class. UV, not PV. Every number names its dashboard and read date.

RULE 4Cost is a product parameter.

Every call logged and routed by tier. A shadow run proves quality holds before cost is cut.
